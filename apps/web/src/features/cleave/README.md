# Cleave

Cleave compares two UTF-8 texts and resolves their Changes on the device. It also resolves git conflict markers in one Marked Text. It uses `@pierre/diffs` 1.6.4, pinned because the Marked Text API is beta.

`cleave.session.ts` owns a Text Diff and stable Conflict IDs. Choices find the current hunk and Change indexes each time. Resolution uses `diffAcceptRejectHunk`, with a newline correction for Accept both at EOF. The Resolved Text comes from the final `additionLines`. The Session preserves CRLF when both inputs use only CRLF. The page shows choices in the main viewer. The separate Resolved Text heading, copy and download buttons, and text panel were removed at the author’s request.

In a Text Diff, Reset clears the choices and keeps Resolve open. Cancel clears the choices, restores the original comparison, and shows Resolve again.

Swap also shows above a Text Diff, outside Resolve. It compares the exchanged texts again and keeps the selected language.

`cleave.marked.ts` owns Marked Text progress. Its browser adapter connects it to the native renderer. The browser adapter uses the vanilla `UnresolvedFile` class and reads each file from `onMergeConflictResolve`. Custom action rows use the shared button styles and translated labels. No code creates conflict markers in user text. See [ADR-0037](../../../../../docs/adr/0037-cleave-resolves-a-text-diff-without-conflict-markers.md).

The comparison header shows removal and addition counts above the viewer. Hover, focus, or press a count to see totals and percentages for lines and characters. Character counts use Unicode code points in changed lines, with line endings excluded. During Resolve, the removal and addition counts include only the Changes that are not settled, so each choice decreases them and Reset or Cancel restores them. The Session stores the size of each Change by Conflict ID and adds the pending sizes. The total line and character counts stay tied to the input texts. The Session changes in place, so the header gets the live statistics as a prop from `view`. That prop changes after each choice, and the `session` prop does not. The Split header shows a copy button for each input text. The Stacked header uses one row for both change counts and one copy button for the Stacked Text. A footer below the viewer shows `lines · characters`, aligned to the right of each Split column or to the bottom right in Stacked layout. Footer totals use the same character rules as the statistics and stay tied to the input texts during Resolve.

`cleave.ts` checks markers, imports strict UTF-8, reads language extensions, and names downloads. On submission, `cleave.language.ts` uses a recognized file extension or detects the language from both input texts with Highlight.js. Detection runs on the device and checks up to 10,000 characters per input. It uses code structure to limit candidate grammars, distinguishes TypeScript annotations from JavaScript, and falls back to Plain text for uncertain input. Users can change the language in the display controls. `cleave.controls.ts` validates preferences and maps controls to renderer options. The browser preference adapter reads and writes localStorage through a writable atom. Text and Resolve progress stay in memory.

The dedicated compare Worker loads on first use. The input stays in place while the compare runs, without a temporary status row. Leaving the page terminates the Worker. The Effect loader also starts the renderer and its JavaScript highlighter on first use. A failed load retries through a separate module graph; the build plugin keeps React shared between the two graphs. Grammars come from the app bundle; a failed grammar falls back to plain text. The service worker caches code after use. An unused grammar needs a network connection on its first use.

Tests use the two boundaries in issue #57: the Session in Vitest, and the page in Playwright. Page tests cover the real renderer, translated actions, file input, and offline use. Session tests check exact Resolved Text bytes.
