# Brand assets are generated from code, and each route has its own Open Graph image

The Ritools brand assets are built by scripts, not drawn and not generated by a model. `apps/web/scripts/generate-brand-assets.ts` writes the wordmark, the compact mark, the PWA icon set, and the Open Graph posters; `apps/web/scripts/capture-pwa-screenshots.ts` writes the manifest screenshots from the running app. The letters are outlines taken from the self-hosted WOFF2 files under `apps/web/public/fonts`, and the cut of the wordmark is the cut of the `Ransom` component, read from the same module the component uses (`apps/web/src/core/libs/ransom-cut.ts`). The script fails when the stylesheet and that module disagree, so the wordmark on disk and the wordmark in the navbar cannot drift apart.

The Open Graph image is one file per route: `/og.png` for the site and `/og/<tool>.png` for a Tool, with the Tool name in ransom letters. A single image for the whole site was the alternative, and it was rejected because every Tool would share one face. An image rendered on request was the other alternative, and it was rejected because it puts an SVG rasterizer inside the Nitro runtime on a host that is not fixed ([ADR-0003](../apps/web/docs/adr/0003-server-rendering-with-tanstack-start.md)).

## Consequences

The assets are committed artifacts, and the build ships them as they are: `pwaAssets` is not set in `apps/web/vite.config.ts` so the icon set is not cut again at build time. A change to the wordmark, the mark, or a poster is a run of the script, not a dropped file into `public/`. Every shipped raster carries its origin in a PNG `tEXt` chunk, so `impeccable embed-prompt --scan apps/web/public` reports nothing missing. The wordmark, the mark, and the posters are vector files, and the font files stay out of them: no asset holds an embedded font, and no asset is bigger than it needs to be.

Adding a Tool means adding its poster: the script reads the Tool catalog, so a new Tool gets its own Open Graph image and its route names it. The images are in the first language the site ships, because the Locale is a cookie and not a path, and one URL has one image.
